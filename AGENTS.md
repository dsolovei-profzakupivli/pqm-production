# Правила роботи Codex у PQM

## Середовище та межі змін

- За замовчуванням розробляй і перевіряй зміни для Sandbox. Production не змінюй без окремого прямого погодження саме на цю дію.
- Працюй у поточній робочій копії та гілці. Не створюй додаткових worktree, копій репозиторію чи гілок без необхідності й погодження.
- Не виконуй push, merge, deployment або зміни конфігурації Render без окремого дозволу. Перевірки GitHub Actions запускай лише в межах погодженого завдання.
- Не запускай Google Writer, синхронізацію, імпорт, Preview, Apply, Resume, recovery, Apps Script чи будь-який запис у Google Sheets або Production без явного погодження. Ізольовані автоматизовані тести з fixtures/mocks дозволені, якщо гарантовано не виконують зовнішніх записів і не змінюють робочі дані.
- Не вважай наявність старих release-інструкцій дозволом на Production. Для Sandbox керуйся актуальним `docs/SANDBOX_RELEASE_PROCESS.md` і конкретним погодженням користувача. Історичні або релізно-специфічні документи не замінюють такого погодження.

## Integrity та Git

- Не змінюй історичні integrity-контракти, manifests, fixtures або SHA pins, щоб пройти тест. Для нових змін використовуй наступний версійований контракт і зберігай попередні перевірки.
- Перед змінами перевіряй `.gitattributes` і `core.autocrlf`. Враховуй різницю CRLF/LF між Windows і Linux; не переписуй масово завершення рядків. Перед commit запускай `git diff --check`.
- У release-звіті вказуй точний повний commit SHA та фактичний стан робочого дерева.

## Перевірки

- Для змін API тестуй реальні HTTP-маршрути, включно з відповідями й параметрами; перевірок лише внутрішніх функцій недостатньо.
- Перед Release Gate перевіряй повноту фактичного staging-пакета, його обов'язкові файли, історичні runner-и та роботу без `.git`.
- Виконуй передбачені workflow повний Python regression, браузерні Playwright-перевірки та Docker/Container Gate. Переконайся, що Gate перевіряє саме погоджений SHA.
- Звітуй окремо про PASS, FAIL, ERROR, SKIP, BLOCKED і незапущені перевірки. SKIP, BLOCKED або відсутній результат не є PASS. Повідомляй також про traceback у фонових потоках, навіть якщо runner завершився успішно.
- Якщо середовище не дозволяє виконати перевірку, назви конкретну причину; не обходь і не послаблюй gate заради успішного статусу.

## Обмеження обсягу

- У суто дизайнерських завданнях змінюй лише представлення. Не змінюй бізнес-логіку, розрахунки й правила дат, призначення УО, фільтрацію або обробку заявок, якщо користувач прямо цього не погодив.
